# Міні-проєкт

# 1. МЕТА РОБОТИ

Розробити утиліту, яка запускає задану програму та відстежує її використання часу CPU, пам’яті та коду завершення.
Після завершення процесу потрібно вивести статистику виконання.
Бажано використати: fork(), exec(), wait4(), getrusage().



# 2. ОПИС РЕАЛІЗАЦІЇ

Програма є консольною утилітою автоматизації та моніторингу. Робота побудована на класичній Unix-архітектурі керування процесами:

- **Ініціалізація:**  
  Головний процес перевіряє наявність аргументів командного рядка (`argc`).

- **Розгалуження (`fork`)**  
  Програма розділяється на два незалежні простори пам'яті: батьківський (монітор) та дочірній (піддослідний).

- **Заміщення образу (`execvp`)**  
  Дочірній процес повністю очищує свою пам'ять і завантажує туди код програми, яку вказав користувач, передаючи їй потрібні прапорці.

- **Неблокуючий моніторинг (`waitpid + WNOHANG`)**  
  Батьківський процес запускає цикл, який кожні 50 мс опитує стан нащадка. Якщо нащадок живий, монітор не зависає, а переходить до збору статистики.

- **Аналіз `/proc`**  
  Через збірку динамічного шляху за допомогою `sprintf` програма відкриває файл `/proc/[PID]/statm`. Звідти зчитується об'єм пам'яті в сторінках, який конвертується в Кілобайти через розмір сторінки системи (`sysconf`). Фіксується максимальний пік (рекорд) споживання ОЗУ.

- **Фінал**  
  Після фіксації завершення нащадка батьківський процес аналізує макроси стану завершення та виводить підсумковий звіт.


# 3. ВИКОРИСТАНІ СИСТЕМНІ ВИКЛИКИ ТА ФУНКЦІЇ

- `fork()` — створення дочірнього процесу.
- `execvp()` — заміна коду поточного процесу новою програмою з автоматичним пошуком у системних папках `PATH`.
- `waitpid()` — контроль стану дочірнього процесу (використано з прапорцем `WNOHANG` для паралельного збору метрик).
- `sysconf(_SC_PAGESIZE)` — запит до ядра Linux для отримання точного розміру однієї сторінки віртуальної пам'яті.
- `usleep()` — мікросекундна пауза процесу монітора для запобігання 100% утилізації ядра процесора порожнім циклом.
- `fopen()`, `fscanf()`, `fclose()` — операції зчитування системних метрик з файлової системи ядра.

# 4. ПЕРЕВІРКА ПОМИЛОК СИСТЕМНИХ ВИКЛИКІВ 

У коді реалізовано захист від збоїв:

- **Вхідні дані:**  
  Перевірка `argc < 2` захищає від запуску без параметрів.

- **Помилка `fork()`:**  
  Якщо в системі немає вільних PID, повертається `-1`, програма переривається через `perror()`.

- **Помилка `execvp()`:**  
  Якщо користувач ввів команду, якої не існує, процес-нащадок перехоплює це, виводить системну помилку та завершується через `exit(1)`.

- **Помилка `fopen()`:**  
  Якщо процес зник швидше, ніж монітор встиг відкрити файл пам'яті, функція повертає `NULL`, оберігаючи програму від критичного вильоту (`Segmentation fault`).

- **Помилка `fscanf()`:**  
  Якщо дані у файлі пошкоджені або неповні, лічильник сторінок примусово скидається в безпечний `0`.

- **Помилка `sysconf()`:**  
  Якщо ядро відмовило в запиті розміру сторінки (повернуло `-1`), програма підставляє безпечне значення.

- **Помилка `waitpid()`:**  
  Якщо виклик повертає `-1` через збій ядра, цикл моніторингу негайно переривається.

- **Аварійне завершення:**  
  Використання макросу `WIFSIGNALED` дозволяє визначити, чи не було піддослідну програму аварійно завершено системним сигналом.
